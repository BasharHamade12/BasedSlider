# Documentation for the scripting language of the code

This project stores decks as plain text in a small custom scripting language (see `src/compiler/`). Documents written in this language are compiled by `src/compiler/index.ts` (`compile()` → lexer → parser) into a `Doc` document model, and serialized back to text by `src/model/serialize.ts` (`serializeDoc()`). An example deck lives in `src/samples/demoDeck.ts`.

## 1. Program structure

```
Program := Slide*
Slide   := 'slide' STRING '{' SlideProperty* '}'
SlideProperty :=
    'background' ':' STRING ';'
  | 'backgroundImage' ':' STRING ';'
  | 'width' ':' NUMBER ';'
  | 'height' ':' NUMBER ';'
  | 'notes' ':' STRING ';'
  | 'id' ':' STRING ';'
  | TransitionBlock
  | Element
```

A program is one or more slide blocks. Inside a slide you can define:

- `background: "#ffffff";` — slide background color. Defaults to `"#ffffff"`.
- `backgroundImage: "data:image/…”;` — optional full-bleed background image (usually a data URL), drawn contain-fit behind every element and never selectable. Typically generated by **Import PDF** (one slide per page with the page as background image) or set from the properties panel. Omitted while unset.
- `width: 960; height: 540;` — optional per-slide canvas size (both together). Defaults to 1920×1080. Set by dragging the canvas corner, from the properties panel, or automatically on **Import PDF**, which sizes the canvas to the page's content box in points — the page's own size minus its blank margins, detected from the rendered pixels and padded with a small ~2% margin so text is not flush against the edge (a Letter page with LaTeX margins imports as roughly `width: 358; height: 598;`), with the cropped higher-resolution raster filling it; "Apply to all slides" copies the current size onto every slide.
- `notes: "Speaker notes text";` — presenter notes, not rendered.
- `id: "s1";` — optional explicit slide id. If omitted an id like `s1`, `s2`, … is generated.
- a `transition { ... }` block (see §2).
- zero or more top-level elements (see §3).

### 1.1 Lexical details

- **Strings** can be double-quoted (`"..."`) or backtick-quoted (`` `...` ``), and may span multiple lines. Escapes: `\\`, `\"`, `\'`, `` \` ``, `\n`, `\r`, `\t`, `\b`, `\f`, `\v`, `\0`. Unknown escapes keep their literal character.
- **Comments** are allowed: `// line comment` and `/* block comment */`.
- **Numbers** are plain decimal literals, optionally negative, with an optional fraction (`-12.5`). No scientific notation.
- **Booleans**: `true` / `false`.
- Property keys are bare identifiers followed by `:` and terminated by `;`.
- Whitespace and blank lines are ignored; semicolons are required after every property, but not after element or block declarations.

### 1.2 Identifier scheme

All ids are auto-generated or user-specified strings of the form `<letter(s)><digits>`. The parser uses these prefixes:

| Prefix | Used for |
| --- | --- |
| `s` | slides |
| `e` | regular elements (shapes, text, latex, code, pen) |
| `c` | connectors |
| `g` | groups |
| `a` | animations |

Duplicate ids within one program are reported as errors; the validator also warns if an id does not match the `[a-z]+\d+` pattern.

## 2. Slide transition

```
transition {
    type: "none";      // 'none' | 'fade' | 'slide' | 'push' | 'zoom'
    direction: "right"; // 'up' | 'down' | 'left' | 'right'
    duration: 400;     // ms
    easing: "easeOut";
}
```

Defaults from `createTransition()`: `type: "none"`, `direction: "right"`, `duration: 400`, `easing: "easeOut"`.

## 3. Elements

```
Element :=
    Shapes    | 'text'    | 'latex'  | 'code'
  | 'image'   | 'html'    | 'figure' | 'pen'    | 'connector'
```

Every element can carry:

| Property | Type | Default | Applies to |
| --- | --- | --- | --- |
| `x` | number | `0` | all except pen (derived) and connector (none) |
| `y` | number | `0` | all except pen and connector |
| `width` | number | `320` (shape), `700` (text), `640` (latex), `720` (code), `640` (image), `720` (html) | all except pen and connector |
| `height` | number | `180` (shape), `120` (text), `140` (latex), `260` (code), `360` (image), `480` (html) | all except pen and connector |
| `rotation` | number (deg) | `0` | shapes, text, latex, code, image, html, pen |
| `opacity` | number 0–1 | `1` | shapes, text, latex, code, image, html, pen |
| `locked` | bool | `false` | all |
| `hidden` | bool | `false` | all |
| `name` | string | — | all (optional cosmetic label) |
| `group` | string | — | all (elements sharing a `group` move/select together; see §11) |
| `members` | string list | — | group lead only: `members: [ "e2", "e3" ];` names the other members (see §11) |
| `animate {}` | block | — | one or more per element (see §10) |

Unknown keys produce a warning and are ignored. Optional blocks a shape/text may contain:

- `text { ... }` — only inside shapes; other element kinds report a warning if they contain one.
- `shadow { x: 0; y: 6; blur: 16; color: "#00000055"; }`.

### 3.1 Shapes: `rect`, `ellipse`, `triangle`, `line`, `polygon`, `star`, `arrow`, `chevron`, `parallelogram`, `trapezoid`, `speech`

```
rect "e1" {
    x: 100; y: 200; width: 400; height: 200;
    fill: "#4c9aff";
    stroke: "#1a1b1e";
    strokeWidth: 2;
    dash: 0;
    radius: 8;              // rect only
    text { content: "Label"; fontSize: 24; color: "#ffffff"; align: "center"; }
    shadow { x: 0; y: 6; blur: 16; color: "#00000055"; }
}
```

All shape kinds share the same property set; their silhouette comes from `shapePath()` in `src/geometry/shapes.ts`. `arrow` is a block arrow pointing right, `chevron` an arrow banner, `parallelogram` a skewed bar, `trapezoid` a narrow-top quadrilateral, `speech` a rounded bubble with a tail.

Defaults from `createShape()`: `fill: "#4c9aff"`, `stroke: "none"`, `strokeWidth: 0`, `dash: 0`, `radius: 8` (rect) or `0` (others).

### 3.2 Text

```
text "e2" {
    x: 120; y: 600; width: 800; height: 120;
    content: "Hello\nworld";
    fontFamily: "Inter, system-ui, sans-serif";
    fontSize: 32;
    fontWeight: 400;
    italic: false;
    underline: false;
    align: "left";
    lineHeight: 1.25;
    letterSpacing: 0;
    color: "#1a1b1e";
    autofit: false;
    math: false;
}
```

**Math mode** (`math: true`, also the "Math mode ($…$ → KaTeX)" checkbox in the
properties panel, available on plain text and on shape labels): every `$…$`
span inside `content` is rendered as inline KaTeX math at the block's font
size, e.g. `"Solve $x^2 + y^2 = r^2$ first"`. Plain segments outside the
dollars keep normal text styling (font, weight, italics, color). Line breaking
and alignment still come from the measured text, so moving/resizing the box
reflows math and text together. Requires balanced `$` pairs per line; a lone
`$` renders literally.

### 3.3 LaTeX

```
latex "e3" {
    x: 200; y: 400;
    content: "\\sum_{i=1}^n i = \\frac{n(n+1)}{2}";
    displayMode: true;    // false = inline math
    fontSize: 32;
    color: "#1a1b1e";     // text color of the rendered math
}
```

Default content from `createLatex()` is the sum formula shown above. `color`
defaults to `"#1a1b1e"` and is serialized only when it differs.

### 3.4 Code block

```
code "e4" {
    x: 300; y: 300; width: 720; height: 260;
    content: "const hello = (name: string) => `Hello, ${name}`;";
    language: "typescript";
    theme: "dark";        // 'dark' | 'light'
    fontSize: 18;
    lineNumbers: true;
    color: "#e6e6e6";
    background: "#1e1e1e";
}
```

### 3.5 Image

```
image "e6" {
    x: 460; y: 300; width: 1000; height: 480;
    src: "https://example.com/chart.png";   // or a data: URL
    fit: "cover";                          // 'contain' | 'cover' | 'fill'
    radius: 12;                            // clipped corner radius
}
```

Defaults from `createImage()`: `src: ""`, `fit: "contain"`, `radius: 0`.

- `src` is any URL the renderer can load, or a `data:` URL. The editor embeds
  picked files as data URLs (raster images are scaled down to 1600 px on the
  longest side), so an exported `.slide` file carries its images with it.
- An empty `src` draws a dashed placeholder box; it is valid and only produces
  a validation warning.
- `fit` maps to the SVG `preserveAspectRatio`: `contain` → `xMidYMid meet`,
  `cover` → `xMidYMid slice`, `fill` → `none`.
- `radius` is serialized only when non-zero, and clips the image with a rounded
  rect.

### 3.6 HTML embed

```
html "e7" {
    x: 620; y: 220; width: 560; height: 340;
    src: "https://example.com/live-widget";   // external page
    // or, instead of src:
    // content: "<!doctype html><h1>Hello</h1>";  // inline HTML source
    radius: 8;   // corner radius
}
```

Defaults from `createHtmlEmbed()`: `src: ""`, `content: ""`, `radius: 8`.

- `src` and `content` are mutually exclusive per convention: **content wins**
  (the editor warns about the ignored `src`, and the serializer only writes `src`
  when `content` is empty).
- An embed with neither source renders a dashed placeholder box and produces a
  validation warning.
- `radius` is serialized only when non-default.
- `reloadToken` is editor-internal bookkeeping for remounting the live frame and
  is never part of the `.slide` language.

### 3.7 Pen (freehand)

Toolbar tip presets (​Classic pen / Pencil / Wide marker / Highlighter​) map to the same model: pencil turns smoothing off, the marker raises minimum thickness and lowers opacity, the highlighter switches the tool. UI keeps `penColor`, `penWidth`, `penOpacity` and the active tip on the UI store.

```
pen "e5" {
    color: "#1a1b1e";
    width: 3;          // stroke thickness, stored on the model as strokeWidth
    smoothing: true;
    mode: "pen";       // 'pen' | 'highlighter'
    points: [
        { x: 10; y: 20; pressure: 0.5; tiltX: 0; tiltY: 0; },
        { x: 40; y: 60; pressure: 0.5; },
    ];
}
```

- `x`, `y`, `width`, `height` on a pen element are **not accepted by the parser**; they are derived from the points (`minX..maxX`, `minY..maxY`) by `normalizePen()`. `rotation` and `opacity` are accepted and serialized only when non-default.
- `pressure` defaults to `0.5`; `tiltX` / `tiltY` are optional.
- At least 2 points are required, or a warning is raised. `strokeWidth` must be positive.

### 3.8 Connector

```
connector "c1" {
    from: "e1:right";                // or a point: { x: 10; y: 20; }
    to: "e2:left";                   // or a point
    routing: "elbow";                // 'straight' | 'elbow' | 'curved'
    startArrow: "none";              // 'none' | 'triangle' | 'open' | 'diamond' | 'circle' | 'bar'
    endArrow: "triangle";
    arrowSize: 14;
    width: 3;
    dash: 0;
    color: "#4c9aff";
    label: "queries";
}
```

Anchors accept three forms: `"elementId"`, `"elementId:port"` where port ∈ `top|right|bottom|left|auto` (defaults to `auto`), and a point `{ x: ..; y: ..; }`. When a referenced element no longer exists, `normalizeDoc()` turns the endpoint into a free point and emits a warning.

Connectors do not use `x/y/width/height/rotation/opacity`; their geometry is derived from `from`/`to`.

### 3.9 Figure

One self-contained, editable object rendered entirely by the canvas — axes, grid, curve or bars are all drawn from the element's properties. There are no child elements, so moving or resizing the figure reshapes the whole drawing.

```
figure "f1" {
    x: 80; y: 90; width: 560; height: 380;
    kind: "graph";              // 'axes' | 'plane' | 'graph' | 'barchart'
    title: "Sine wave";         // caption drawn above the plot (may be empty)
    fn: "sine";                 // graph only: 'line' | 'quadratic' | 'cubic' | 'sine' | 'exp'
    a: 2; b: 1.5; c: 0.5;       // coefficients of the selected family
    domain: 8;                  // graph only: x plotted over [-domain, domain]
    values: [ 10, 30, 20, 45 ];// barchart only: bar heights
    axisColor: "#1a1b1e";
    gridColor: "#d9dde3";
    accentColor: "#4c9aff";
    titleColor: "#1a1b1e";
}
```

Defaults from `createFigure()`: `kind: "graph"`, `fn: "quadratic"`, `a: 1`, `b: 0`, `c: 0`, `domain: 5`, `axisColor: "#1a1b1e"`, `gridColor: "#d9dde3"`, `accentColor: "#4c9aff"`, `titleColor: "#1a1b1e"`. `fn`/`a`/`b`/`c`/`domain` only apply to `kind: "graph"`, `values` only to `kind: "barchart"`.

Reshape the graph from the properties panel (curve family, coefficients, domain) or the script; the whole figure stays a single selectable/movable object.

## 6. Colors

Any CSS color string: `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb(...)`, `rgba(...)`, `hsl(...)`, `hsla(...)`, `none`, `transparent`. Unknown / unrecognized strings raise a warning, not an error.

## 7. Easing

`'linear' | 'ease' | 'easeIn' | 'easeOut' | 'easeInOut' | 'backOut'`

## 8. Validation

Two levels, reported by `validateDoc()`:

- **error** — duplicate element/slide/animation ids, missing required `from`/`to`, non-string content, non-numeric geometry, negative width/height, connector pointing at a missing element.
- **warning** — unknown properties, unknown color, unknown effect/easing/direction/arrow/routing/transition, pen with < 2 points, non-positive connector/pen width, non-positive code font size, wrong id shape.

## 9. Serialization round trip

`serializeDoc(doc)` is deterministic and produces canonical text: identical documents always serialize to identical text. Notes:

- Deck metadata (`title`, `version`, slide `width`/`height`) is **not** part of the language; it is managed by the editor.
- Slides are separated by a blank line; elements by a blank line inside a slide.
- Strings are always double-quoted with backslash escaping.
- Only non-default properties are printed, so editing a value back to its default removes the line again on re-save.
- Elements ordered by their position in the slide, slides ordered by position in the deck; inserting or duplicating preserves relative order.

## 10. Animations

```
animate {
    id: "a1";              // optional explicit id; auto-assigned otherwise
    effect: "fadeIn";      // see table below
    trigger: "afterPrevious"; // 'onClick' | 'withPrevious' | 'afterPrevious'
    duration: 500;         // ms
    delay: 0;              // ms
    easing: "easeOut";
    direction: "up";       // for slideIn/slideOut only
    repeat: 1;
}
```

| Category | Effects |
| --- | --- |
| Enter | `fadeIn`, `slideIn`, `zoomIn`, `drawLine` |
| Exit | `fadeOut`, `slideOut`, `zoomOut` |
| Emphasis | `pulse`, `bounce`, `spin`, `flash` |

Defaults from `createAnimation()`: `effect: "fadeIn"`, `trigger: "afterPrevious"`, `duration: 500`, `delay: 0`, `easing: "easeOut"`, `direction: "up"`, `repeat: 1`.

Effects are scheduled in Present mode as follows (see `src/presentation/schedule.ts`): enter and emphasis animations are grouped into steps; a new step starts at each `onClick` trigger, and elements with an enter animation start hidden. Exit animations run when leaving the slide.

## 11. Groups

Set the same `group` value on several elements to make them move, select, delete and duplicate as one unit. There is no dedicated `group` block; it is just element properties.

One member of the group is the **lead**: the element with the lowest numeric id. The lead repeats the `group` tag and additionally carries the `members` list naming every other member:

```
rect "e1" {
    x: 100; y: 100; width: 200; height: 120;
    group: "g1";
    members: [ "e2", "e3" ];
}
rect "e2" {
    x: 350; y: 100; width: 80; height: 80;
    group: "g1";
}
text "e3" {
    x: 100; y: 240; width: 300; height: 60;
    content: "caption";
    group: "g1";
}
```

Rules:

- Non-lead members must not carry a `members` list; validation warns about a member listing itself or referencing a missing id.
- Old decks that only repeat the `group` tag stay valid — the members list is an explicit hint, and the group keeps working from the tag alone.
- Deleting a member keeps the group: the remaining lowest id becomes the lead and owns the surviving list. Ungrouping clears the tag and any lists.

In the editor: select elements and use **Group / Ungroup** in the Arrange panel or **Ctrl/Cmd+G** / **Ctrl/Cmd+Shift+G**. Clicking any member selects the whole group; the toolbar's math-figure menu inserts a single `figure` element (§3.9), so it can be grouped like any other object.

## 12. Compile API

```
import { compile } from "./compiler";
const result = compile(sourceText);
// result.doc     : Doc | null   (null only when a hard error occurred)
// result.errors  : Diagnostic[] (severity 'error' | 'warning', phase 'lex' | 'parse' | 'validate' | 'action')
```

Import / export from the toolbar uses the same text format: the Import button and Export button both round-trip through `serializeDoc` / `compile`.
